# Model artifact layout

`models/` contains the local filesystem layout used to register or deploy model artifacts. Large learned weights are intentionally excluded from Git, while the small files needed to identify and reproduce an experiment should be versioned.

## PatchCore model folder

The minimum initial layout for one G01 PatchCore experiment is:

```text
models/
└── Patchcore_<preprocessing_id>_256_c10_seed42/
    ├── G01.ckpt                 # required locally; ignored by Git
    └── G01.metadata.json        # required; commit after reviewing for secrets
```

The checkpoint and metadata must keep the same stem (`G01`). Model Lab locates the metadata beside the checkpoint and uses its `dataset.preprocessing_id` to locate the matching versioned configuration under `training/preprocessing/configs/`.

The metadata generated by `training.models.train_patchcore` already records the model family, angle, model set, input size, backbone/layers, coreset ratio, neighbor count, seed, manifest hash, preprocessing ID, split counts, software, hardware, command, and Git state. Do not edit these facts to make a model appear compatible. Model Lab hashes the checkpoint and validates the declared manifest and preprocessing contract during registration.

## What belongs in Git

Commit these small reproducibility artifacts:

- `G01.metadata.json` after checking that it contains no secret or sensitive local information;
- model-folder README files and approved bundle/deployment descriptors;
- preprocessing JSON configurations under `training/preprocessing/configs/`;
- the preprocessing model registry and recorded artifact hashes;
- calibration configuration/provenance after validation selects a threshold;
- frozen dataset manifests, experiment reports, and small metric/result summaries.

Do not commit these large or machine-local artifacts:

- `*.ckpt`, `*.onnx`, `*.pt`, `*.pth`, or other learned weight files;
- raw or preprocessed images, derivative datasets, masks, or anomaly-map arrays;
- `.model_lab/` imports, cache, registry, comparison results, or locked-test state;
- Lightning logs, temporary outputs, or machine-specific dataset paths.

The ignored checkpoints and preprocessing weights need durable storage outside Git, with their SHA-256 hashes retained in versioned metadata. GitHub Releases, an object store, or another controlled artifact store is preferable to ordinary Git. Git LFS is also possible later, but this repository does not currently configure it.

## Preprocessing dependencies

Raw letterbox and fixed crop have no learned preprocessing weight. Live U2-Net/rembg preprocessing additionally requires:

```text
models/preprocessing/rembg/u2net.onnx
```

That ONNX file remains ignored by Git. Its expected identity is recorded in `training/preprocessing/configs/model_registry.json`. Verified derivative datasets can be reused by Model Lab without rerunning preprocessing, but **Force live preprocessing** and production inference require the local weight.

The black-background arm resolves the full `rembg_u2net_gray_v1` segmentation/alignment parent and then composites the same mask on black. It does not use an independent anomaly or preprocessing checkpoint.

## Calibration

The current stage-one checkpoints do not yet have an approved image threshold. Register them as uncalibrated: raw-score distributions and latency remain available, while PASS/FAIL and false-positive rate remain unavailable. Do not create a placeholder threshold merely to make the UI show decisions.

After validation and the acceptable false-positive rate are agreed, retain the threshold together with its calibration method, source manifest hash, split, selected-sample identity hash, target FPR, and timestamp. That small calibration artifact should be versioned; the checkpoint should remain ignored.
